<objective>
Fix Put.io transfer and file data cleanup after Sonarr/Radarr confirms import.

Purpose: Currently transfers are never cleaned up from Put.io because WatchForSeeding polls a stale local snapshot that never changes status. This fix implements two paths: (1) immediate cleanup when no seed ratio is configured, and (2) ratio-based cleanup when PUTIO_SEED_RATIO is set — both using exponential backoff and treating "transfer not found" as success.
Output: Put.io transfers and their file data are deleted after import confirmation. PUTIO_SEED_RATIO env var controls optional seeding window before cleanup.
</objective>

    1. Add `import "github.com/cenkalti/backoff/v5"` and `"strings"` to imports (backoff is already in go.mod).

    2. Add `CleanupTransfer(ctx context.Context, t *transfer.Transfer)` method on `*Downloader`:
       - Compute `hash := sha1.Sum([]byte(t.ID)); hashStr := hex.EncodeToString(hash[:])`
       - Use the v5 backoff API to retry with max 3 attempts:
         ```go
         _, err := backoff.Retry[struct{}](ctx, func() (struct{}, error) {
             if err := d.tc.RemoveTransfers(ctx, []string{hashStr}, true); err != nil {
                 if strings.Contains(err.Error(), "transfer not found") {
                     d.logger.InfoContext(ctx, "Put.io transfer already removed, treating as success",
                         "transfer_id", t.ID, "transfer_name", t.Name)
                     return struct{}{}, nil
                 }
                 return struct{}{}, err
             }
             return struct{}{}, nil
         }, backoff.WithMaxTries(3))
         ```
       - If `err != nil` after retry: log error ("failed to clean up Put.io transfer after retries, continuing", "transfer_id", t.ID, "err", err) and return — do not crash.
       - On success (err == nil and no "not found" path): log info ("Put.io transfer and files cleaned up", "transfer_id", t.ID, "transfer_name", t.Name).

    3. Update `WatchForSeeding` signature to `(ctx context.Context, t *transfer.Transfer, pollingInterval time.Duration, seedRatio float64)`.

    4. Replace the body of `WatchForSeeding` to use live polling:
       - Keep the goroutine, panic recovery, ticker, and context.Done() patterns.
       - In the ticker case: type-assert `d.dc` to `*putio.Client` (same pattern as existing code). If assertion fails, log error and return.
       - Call `putioClient.GetTransferInfo(ctx, t.ID)`.
       - If `found == false`: log info ("transfer no longer exists on Put.io, cleanup already done", "transfer_id", t.ID) and return from goroutine.
       - If err != nil: log error and `continue` (retry next tick).
       - If `uploadRatio >= seedRatio`: log info ("seed ratio reached, cleaning up transfer", "upload_ratio", uploadRatio, "target_ratio", seedRatio), call `d.CleanupTransfer(ctx, t)`, return.
       - Remove any reference to `t.IsSeeding()` — that stale snapshot check is what broke the original implementation.
