<objective>
Detect missing/deleted Put.io transfers in the download error path, emit warn-level logs, send distinct Discord embed notifications for "transfer removed" vs "files missing" cases, mark transfers as "missing" in DB to prevent re-processing, and clean up partial local files.

Purpose: When Put.io transfers or their files disappear (user manual deletion, Put.io expiry, etc.), the pipeline currently treats these as generic download errors. This phase makes these failures explicit, informative, and non-repeating.

Output: Updated downloader with missing-transfer detection, Discord embed notifications, and DB status tracking.
</objective>

**Detection paths for the two cases (per locked user decision — both MUST be implemented):**

- **"Files missing" (`ErrTransferFilesNotFound`):** Transfer appears in `Transfers.List` but `Files.Get`/`Files.URL` fails for its FileID. The content was deleted while the transfer record remained. Detected in `GrabFile` and `GetTaggedTorrents`.

- **"Transfer removed" (`ErrTransferNotFound`):** A transfer was previously claimed (had files, got status `downloading` in DB), but by the time `DownloadTransfer` runs, `len(transfer.Files) == 0`. This happens when a previously-seen transfer's files were cleaned between polling cycles. Detected in `DownloadTransfer` — see step 3 below.

b) **Files missing detection:** In the `wg.Go` closure, after `d.DownloadFile` returns an error, check `errors.Is(err, putio.ErrTransferFilesNotFound)`. If so:
- Log at warn level: `logger.WarnContext(ctx, "transfer files missing from Put.io", "transfer_id", transfer.ID, "transfer_name", transfer.Name, "file_path", file.Path)`
- Clean up any partial local files for this transfer: `os.RemoveAll(filepath.Join(d.downloadDir, transfer.Name))`
- Return the error (wrapping `ErrTransferFilesNotFound`) so it propagates up through `wg.Wait()` to `WatchDownloads`
- Do NOT emit to `OnTransferMissing` here — that is `WatchDownloads`'s job

**CRITICAL — single emission point:** `DownloadTransfer` MUST NOT send to `OnTransferMissing`. It only returns errors. `WatchDownloads` is the single place that reads the error and routes to the correct channel. This avoids double-emission on the unbuffered channel and guarantees exactly one warn log per missing-transfer event.

**In `WatchDownloads`** — after `d.DownloadTransfer` returns an error, classify and route:
```go
downloadedFiles, err := d.DownloadTransfer(ctx, transfer)
if err != nil {
    if errors.Is(err, putio.ErrTransferNotFound) {
        logger.WarnContext(ctx, "transfer removed from Put.io", "transfer_id", transfer.ID, "transfer_name", transfer.Name)
        d.OnTransferMissing <- MissingTransferEvent{Transfer: transfer, MissingType: "transfer_removed"}
        continue
    }
    if errors.Is(err, putio.ErrTransferFilesNotFound) {
        // Warn log already emitted inside DownloadTransfer for the specific file
        d.OnTransferMissing <- MissingTransferEvent{Transfer: transfer, MissingType: "files_missing"}
        continue
    }
    logger.ErrorContext(ctx, "failed to download transfer", "download_id", transfer.ID, "err", err)
    d.OnTransferDownloadError <- transfer
    continue
}
```

**Logging discipline:** Exactly one warn log fires per missing-transfer detection event:
- For `ErrTransferNotFound`: the warn log is emitted in `WatchDownloads` (not inside `DownloadTransfer`, which just returns the error).
- For `ErrTransferFilesNotFound`: the warn log is emitted inside `DownloadTransfer` at the file level (with file path context). `WatchDownloads` does NOT log again — it only routes to the channel.

**Important:** Import `"github.com/italolelis/seedbox_downloader/internal/dc/putio"` in the downloader package. This avoids the circular dependency. The `transfer` package already defines the shared types — adding sentinel errors there is consistent.
